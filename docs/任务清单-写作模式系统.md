  - 文件：`src/Agent/tools/creativeTools.ts`、`src/Agent/useAgentSession.ts`
  - 验收：空书写第一章不报「缺少细纲」；老书续写不受影响

## 2. C2 上下文建立

- [ ] **T2.1 老书上下文参数 8+2**
  - `buildOutlineWritingContext` 调用处 `archiveCount: 9→8, proseCount: 1→2`
  - 文件：`creativeTools.ts:233`、`productionTools.ts:26`、`outlineWritingContext.ts`（默认值同步）

- [ ] **T2.2 新书上下文降级组装**
  - 新书时 `buildStoryCanonBlock` 剧情卡/角色卡为空 → 降级文案「本书无前文，以设定卡 + 开局方向为承接依据」

  - 验收：新书复盘 prompt 不再出现「按已有正文承接」误导文案

## 3. C3 写前决策

- [ ] **T3.1 方向卡生成**（新增）
  - 新 prompt：`buildOpeningOptionsPrompt`——输入设定卡 + 角色卡 + genre_play 开篇打法；输出 2-3 个方向，每个含 `{title, pitch, outline, risk}`
  - 强约束：只基于书内已填设定，不编造新设定
  - 文件：新增 `src/Agent/openingDirection.ts`
  - 验收：新书对话里 Agent 出 2-3 个方向卡，无编造设定

- [ ] **T3.2 方向选择交互**（新增）
  - 复用 `AgentChatPanel.tsx:4936` 确认流：气泡渲染方向选择卡（2-3 选项），点选后把选中方向转成后续出纲指令
  - 文件：`AgentChatPanel.tsx`（加分支，不动原确认流）
  - 验收：点选方向后按该方向进入故事核心档案固化（wizard 下一步）

- [ ] **T3.3 故事核心档案**（新增）
  - 新 prompt：把选中方向固化为五要素（主角/世界/核心冲突/长线目标/爽点模型），用户确认
  - 文件：`openingDirection.ts` 内新增或独立文件
  - 验收：档案卡五要素齐全，可被后续规划引用

- [ ] **T3.4 写法决策**（新增）
  - 新 prompt：叙事视角 / 节奏基调 / 差异化打法 / 读者定位，用户确认
  - 文件：`openingDirection.ts` 内新增
  - 验收：写法决策卡产出，且与方向/档案不冲突

- [ ] **T3.5 新书 wizard 多步确认状态机**（新增）
  - 跨步状态由谁持有：新书模式从方向卡 → 档案 → 写法决策 → 剧情规划 → 大纲 → 大纲审查共 6 步，每步都要「用户确认后才进下一步」（同题材研究为独立 C4 环节，按需插在写法决策之后，不占 wizard 步骤）
  - 定义 `agentTaskState`（或 AgentChatPanel 局部 state）字段：`{ step: number, direction: 选中方向, coreArchive: 档案, writingApproach: 写法决策, plotPlan: 剧情规划, outline: 大纲, outlineReview: 审查结果 }`
  - 状态在对话进行中内存持有；关键选择落 `agentMemory` / taskSheet 供后续 step 引用
  - 文件：`AgentChatPanel.tsx`、`useAgentSession.ts`（state 定义处）
  - 验收：6 步按序推进，任一步用户可回退/修改，不丢失已确认的先前决策

  - 来源标注强制：引用实读内容或「基于训练知识，非实时」，不许无来源断言
  - 文件：新增 `src/Agent/researchPrompt.ts`
  - 验收：研究结论卡有来源标注，能落到本书差异化

## 5. C7 Agent 看章节（读正文）

> 决策（2026-08-03 已定）：**只做笔趣阁系等公开低反爬免费站**；番茄（字体加密）、起点（验证码）不做，遇到直接返回「该站反爬无法读取」。

- [ ] **T5.1 open_webpage 工具**（新增）
  - Agent 工具 `open_webpage(url)`：内部封装 `novel_browser_open` / `novel_browser_navigate`（已有 Rust 命令）
  - 需解决窗口依赖：NovelLab 窗口未开时，给 Agent 独立隐藏 webview 实例或明确报「浏览器组件未就绪」
  - 文件：新增 `src/Agent/tools/webpageTools.ts`
  - 验收：Agent 能打开笔趣阁系任意书页/章节页 URL

- [ ] **T5.2 extract_page_text 工具**（新增）
  - Agent 工具 `extract_page_text(selector?)`：内部 `novel_browser_execute_js` 提取正文
  - 默认策略：常见正文容器（`#chaptercontent` / `#content` / `.content` / `article`）命中即取；章节文本截断 3000-5000 字
  - 文件：`webpageTools.ts` 内新增
  - 验收：笔趣阁系章节页能提取出干净正文（实测 `#chaptercontent` 可用）

- [ ] **T5.3 read_url fallback**
  - 静态站（无 JS 渲染）优先 `read_url`（reqwest，已有）更快更省；novel_browser 留给 JS 渲染站
  - 文件：`webpageTools.ts` 内策略
  - 验收：同一 URL 两种路径都能读到内容，fallback 不报错

- [ ] **T5.4 反爬边界处理**
  - 提取结果为空/乱码/验证码页 → 返回「该站反爬无法读取」，不硬闯、不重试 N 次
  - 文件：`webpageTools.ts` 内判断（正文长度阈值 + 乱码特征）
  - 验收：番茄/起点 URL 返回明确「无法读取」，不卡死、不编造内容

## 6. C5 大纲生成与有效性审查

- [ ] **T6.0 剧情规划（卷级，新增）**
  - 新 prompt：`buildPlotPlanPrompt`——输入核心档案 + 写法决策 + 同题材研究结论；输出第一卷规划：`{ 卷目标, 冲突递进（3-5 阶段）, 主要角色弧线, 卷末钩子 }`
  - 层级定位：在 `plotOutline` 大纲体系之下、章节级大纲之上；与现有 `plotOutline` 字段衔接（写入或对齐，不重复造）
  - 用户确认后才进章节大纲
  - 文件：`openingDirection.ts` 内新增或独立 `plotPlanning.ts`
  - 验收：卷规划产出覆盖「目标/冲突递进/角色弧线/卷末钩子」，且与 plotOutline 不冲突

- [ ] **T6.1 章节级大纲生成**（新增）
  - 新 prompt：每章 `{核心事件, 节拍, 承担的剧情功能}`，基于剧情规划展开
  - 文件：新增 `src/Agent/outlineReview.ts` 或并入 openingDirection
  - 验收：大纲覆盖卷内全部目标章，每章有明确功能

- [ ] **T6.2 大纲有效性审查**（新增）
  - 新 prompt：逐章判定剧情有效/无效——有效 = 推进主线/塑造人物/兑现爽点/制造冲突；无效 = 注水/重复/偏离目标 → 标记并给修改
  - 审查结果用户可确认、可否决，不自动覆盖大纲
  - 文件：`outlineReview.ts` 内新增
  - 验收：能标记出无效剧情并给出修改；用户否决后不覆盖

## 8. 老书模式

- [ ] **T8.1 理解模型组装**
  - 老书建模 = memoryBank 章梗概 + archiveRecords + roleCard + 风格分析器，按模式组装成「书的理解」
  - 全部来自已有数据，0 额外模型调用
  - 文件：新增 `src/Agent/bookUnderstanding.ts`
  - 验收：老书首次续写前能展示完整「书的理解」

- [ ] **T8.2 对齐卡片（首次确认一次）**
  - 首次建模/关键状态变更时，向用户展示「我理解你的书目前状态如下」；确认后后续续写不重复确认
  - **「已确认」标志落点（定死）**：存书级字段 `book.agentContextConfirmed: boolean`（默认 false）；首次确认 → true；书内容/档案关键变更（`plotOutline`、角色卡、memoryBank 章节新增）时重置 false。持久化随 `Book` 对象保存（与书库落盘一致），不另开 localStorage
  - 文件：`AgentChatPanel.tsx`（复用确认流）、`bookUnderstanding.ts`（读取/重置标志）、book store（保存字段）
  - 验收：首次确认一次后 `book.agentContextConfirmed = true`，后续续写直接走；关键变更后重置，重新弹一次
