# 写梨眼 Agent 写作模块：新书 / 老书分流写作 —— 总目标计划书

> 版本：v1（2026-08-03）
> 性质：模块级目标蓝图（做什么效果），不含排期与分期
> 关联现状：
> - 新书当前「压根没法写」：`write_chapter_body` hasOutline 硬检查 + 右键拦截双堵
> - 老书已有完整链路：读上文 → runPlanning → 写前复盘 → 写正文 → 写后 review
> - 已存在可复用件：`bookHasNoSubstantialBody` 判定、章纲确认流、plan_chapter_outline、写前复盘五问

---

## 1. 模块是什么

「写作前置」模块。负责 Agent 动笔之前的所有准备：判断这本书处于什么阶段、该读哪些上下文、该形成什么写作决策、该让用户参与哪些选择——然后把一个「有依据、有方向、可确认」的写作任务交给正文生成。

一句话定位：**让 Agent 无论面对新书还是老书，都能在「读对了、想清楚了、用户认了」之后才动笔。**

## 2. 模块要达成的总效果

> 新书能写、老书写得准、动笔前有可见决策、开局有用户参与、全程不编造。

拆成五条可感知的效果：

| # | 效果 | 含义 |
|---|---|---|
| E1 | **新书能写** | 一本只有书名/简介/设定填空的新书，用户说「写第一章」，Agent 能走通全链路产出第一章，不被「缺少细纲」卡死 |
| E2 | **老书写得准** | 老书续写自动带上足够的剧情档案和近章正文，承接点、人物状态、未收线头都对齐，不跳戏 |
| E3 | **动笔前有可见决策** | 每次写作前，用户能看到 Agent 的「写前复盘」：承接什么、怎么写、为什么、爽点节奏——不是黑盒直接吐正文 |
| E4 | **开局有用户参与** | 新书第一版不是 Agent 自说自话，而是先给 2-3 个开局方向让你选、让你改，你点头后才展开 |
| E5 | **全程不编造** | 所有决策基于书内已填设定 + 题材打法，不联网搜、不发明「市场流行 X」、不凭空造设定 |

## 3. 模块能力构成（完整链路）

### 3.1 分流判定
- 识别一本书处于哪个阶段：**新书**（无任何实质正文）/ **老书**（已有正文）
- 判定依据：`bookHasNoSubstantialBody`（对章数、wordCount、正文内容的综合判断）
- 分流结果决定后续整条链路走向，是模块的入口

### 3.2 新书链路（从零到第一章）
```
书内设定（世界设定/大纲/角色卡/简介）
   + 题材打法（genre_play 开篇节奏模板）
        │
        ▼
① 开局方向生成：2-3 个跨章开局方向
   （每个含：标题卖点 / 一句话 pitch / 跨章走向 / 风险点）
        │
        ▼
② 用户选择：点选一个方向，或提出修改意见
        │
        ▼
③ 按选定方向出第一章细纲（plan_chapter_outline）
        │
        ▼
④ 用户确认 → 落正式细纲（formalize_chapter_outline）
        │
        ▼
⑤ 写前复盘（五问，基于细纲对齐）
        │
        ▼
⑥ 写正文 → 写后 review → 交稿
```
**效果**：新书的第一章是「用户参与选出来的」，不是模型拍脑袋写的。

### 3.3 老书链路（续写已有正文）
```
前 8 章剧情档案 + 近 2 章正文尾部
        │
        ▼
① runPlanning（结构化约束：必含节拍/禁止动作）
        │
        ▼
② 写前复盘（承接点/怎么写/为什么/加什么少什么/爽点节奏）
        │
        ▼
③ 写正文（细纲 + 复盘决策 + 硬约束三保险）
        │
        ▼
④ 写后 review（hard/soft 问题检查 → 必要时修订 1 次）
```
**效果**：老书续写上下文充足、承接准确、写完自检，用户看到的不只是正文，还有「为什么这么写」。

### 3.4 两条链路的公共能力
- **上下文装配**：剧情档案按章梗概压缩（token 友好），近章正文取尾部；新书时自动降级为「设定卡 + 开局方向」
- **写前复盘**：一次短生成（~1200 token）形成写作决策，决策文本给用户看、决策 JSON 约束写手；失败降级不阻塞
- **写后验收**：复盘是计划、review 是验收，职责分离；复盘 add 的线头不进 memoryBank，防双写
- **设置开关**：写前复盘可关（默认开），关闭后链路退化为纯写作

## 4. 用户能看到的体验（模块成型后）

**新书场景**（对话里说「写第一章」）：
1. Agent 气泡里出现「开局方向」卡片：2-3 个方向，各带一句话卖点和走向
2. 你点选一个 / 说「第二个，但主角晚点出场」
3. Agent 按你的选择出第一章细纲 → 你确认
4. 琥珀色「写前复盘」卡片展示这章怎么打
5. 正文产出，写完自检

**老书场景**（对话里说「继续写」）：
1. 「写前复盘」卡片先出现（承接/怎么写/爽点/章末）
2. 正文直接产出
3. 有硬伤时 Agent 自动修订一次再交稿

**编辑器场景**：
- 右键「按细纲写作」：有细纲 → 正常写；没细纲 → 引导去对话里先出方向/章纲，不再干瞪眼

## 5. 质量目标

| 维度 | 目标 |
|---|---|
| 可用性 | 新书老书全链路都能走通，无「压根写不了」的死角 |
| 可靠性 | 复盘/方向解析失败一律降级不抛错；缺细纲有引导不卡死 |
| 忠实性 | 决策只基于书内设定 + 题材打法；题材打法内容写死防编造 |
| 可见性 | 写作决策全程对用户可见，非黑盒 |
| 成本 | 复盘单次 ≤1200 token；老书上下文增量可控（8 档案 + 2 正文） |
| 一致性 | 复盘计划与 review 验收职责分离，不互相污染 |
| 质量保障 | tsc 通过 + 全量测试绿 + 新链路有单测覆盖 |

## 6. 模块边界（明确不管的事）

- **不联网**：不搜市场/榜单/热点，题材打法来自内置技能文件
- **不动工坊/批量路径**：工坊已有自己的新书逻辑（bookHasNoSubstantialBody），本模块只负责 Agent 对话/编辑器写作路径
- **不做静默自动开局**：新书开局必须用户参与选择，不自动拍板
- **不新造 UI 面板**：方向选择、章纲确认都复用现有气泡确认流
- **不改变写后 review 已有行为**：它继续按原逻辑验收

## 7. 模块完成的定义

当以下全部成立，视为模块建成：
1. 新书从零写第一章走通全链路（含开局方向选择）
2. 老书续写自动带 8 档案 + 2 正文，承接准确
3. 每次写作前都有可见的写前复盘
4. 所有新代码有测试，全量测试绿
5. 用户实际使用一轮：新书写一章、老书续一章，全程无卡死、无编造、决策可见
