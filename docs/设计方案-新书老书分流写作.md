## 0. 问题背景（已核实）

新书（无实质正文）和老书走同一套流程，但新书会撞墙：

1. **对话续写**：`write_chapter_body` 的 `hasOutline` 硬检查（creativeTools.ts:240）→ 新书没细纲直接报「缺少细纲」拒绝写
2. **编辑器右键「按细纲写作」**：EditorContextMenu.tsx:450 前置拦截 `if (!outlineText) return warning('请先填写细纲')` → 同样堵死
3. **写前复盘**：新书时 `buildStoryCanonBlock` 剧情卡/角色卡全空，降级为「（无设定卡）」，复盘无承接可依
4. **上下文装配**：`buildOutlineWritingContext` 前 9 章档案 + 近 1 章正文，新书全部 clamp 到 0

**结论**：新书现在不是「写得差」，是**压根没法写**。分流是硬需求。

---

## 1. 总目标

```
新书（bookHasNoSubstantialBody = true）
   读设定卡 + 角色卡 + genre_play 开篇打法
   → Agent 出 2-3 个跨章开局方向（用户选择）
   → 用户选/改 → 出第一章细纲 → 确认 → 写前复盘 → 写正文 → 写后 review

老书（有前文）
   前 8 章剧情档案 + 近 2 章正文
   → runPlanning → 写前复盘（细纲对齐）→ 写正文 → 写后 review
```

两个原则：
- **搜索 = 书内设定 + 角色卡 + genre_play**，不联网、不编造市场信息（延续写前复盘立的规矩）
- **交互复用现有确认流**（AgentChatPanel 气泡 + 确认按钮），不新造面板

2. 老书上下文顺带改善（8+2）
3. 零新增 prompt、零新增交互、低风险

### 任务清单

| # | 文件 | 改动 | 类型 |
|---|---|---|---|
| P1-1 | `src/Agent/tools/creativeTools.ts` | `write_chapter_body` 缺细纲时，返回从「报错」改为「可执行指令」：明确告诉模型 —— 本书无前文 → 先 `plan_chapter_outline` 生成章纲 → 等用户确认 → `formalize_chapter_outline` 落细纲 → 再回来调 `write_chapter_body` | 改返回逻辑 |
| P1-2 | `src/Agent/outlineWritingContext.ts` + 两个调用方（creativeTools.ts:233、productionTools.ts:26） | 老书上下文参数：`archiveCount: 9→8`，`proseCount: 1→2`（近 2 章正文尾部，各 1800 字；token 增量 ≈ 1800 字，可接受） | 参数 |

### 验收标准

- [ ] 右键没细纲章：提示引导文案，不再只报「请先填写细纲」

### 排期估计
半小时到一小时量级，纯接线。

## 3. P2：开局方向交互（中，真正的新增量）

### 目标
新书不是模型自由发挥，而是**结构化开局决策**：2-3 个跨章开局方向 → 用户选 → 按选定方向出细纲。

### 任务清单

| # | 文件 | 改动 | 类型 |
|---|---|---|---|
| P2-1 | 新增 `src/Agent/openingDirection.ts` | 新 prompt 构建：`buildOpeningOptionsPrompt({book, chapter, genreBlock})` —— 输入 = 设定卡（buildNovelSettingCard）+ 角色卡 + genre_play 开篇打法；输出 schema：2-3 个方向，每个含 `{title, pitch(一句话卖点), outline(跨章走向 2-4 句), risk(风险/难点)}`；强约束「基于书内已填设定，不编造新设定」 | 新增 |
| P2-2 | 新增工具 `plan_opening_direction`（或扩展 plan_chapter_outline 加 mode） | 新书分流后第一个工具调用；产出方向 JSON + 展示文本；`needsConfirm: true`（走现有确认流） | 新增工具 |
| P2-3 | `src/Agent/AgentChatPanel.tsx` 确认流扩展 | 复用 4936 行的确认模式：气泡渲染「开局方向选择卡」（2-3 个选项按钮），用户点选后把选中方向转成后续 plan_chapter_outline 的指令 | 接线 |
| P2-4 | `src/Agent/tools/creativeTools.ts` | `write_chapter_body` 引导消息升级：缺细纲且新书 → 指向 `plan_opening_direction`（而非 P1 的 plan_chapter_outline） | 改引导 |
| P2-5 | `src/Agent/preWriteReflection.ts` | 新书场景 `runPreWriteReflection` 的承接上下文：剧情卡空时，文案改为「本书无前文，以开局方向 + 设定卡为承接依据」，不让模型空想「上一章停在哪」 | 小改 |

### 验收标准
- [ ] 新书对话让 Agent 写第一章：Agent 先出 2-3 个开局方向（卡片/气泡），用户点选一个
- [ ] 点选后按该方向出第一章细纲（plan_chapter_outline），用户确认 → formalize → 写正文
- [ ] 方向选项内容全部来自书内设定 + genre_play，无编造新设定（抽查 prompt 与输出）
- [ ] 用户可改：选完方向后还能说「第二个方向，但主角晚点出场」之类修改意见，Agent 按意见调整再出纲
- [ ] 全量测试绿

### 排期估计
1-2 天量级（prompt 设计 + 工具 + 确认流接线）。

## 4. 分期依赖关系

```
P1（接线）          P2（新增量）
  │                   │
  ├─ P1-1 引导消息 →──┼─ P2-4 引导升级（把 plan_chapter_outline 换成 plan_opening_direction）
  ├─ P1-2 8+2 参数 ── 独立，P2 不依赖
  ├─ P1-3 新书判定 ──→┼─ P2-2 工具触发条件（bookHasNoSubstantialBody）
  └─ P1-4 右键文案 ── 独立
                      └─ P2-1/P2-3/P2-5 全新
```

**依赖**：P2 依赖 P1 的分流判定（P1-3）。P1 不依赖 P2，可独立交付。
**建议**：P1 先做先验（解除墙，立竿见影）；P2 出规格文档再实现。

## 5. 风险与边界

| 风险 | 等级 | 对策 |
|---|---|---|
| P1 阶段模型自由发挥，新书引导可能不按指令走（不调 plan → 直接 write 又撞墙） | 中 | P1 只是「解墙」过渡，P2 的结构化方向才是正解；验收只要求「不卡死」 |
| 8+2 让老书上下文多 ~1800 字，长书/慢模型变慢 | 低 | 可接受；若实测慢再降回 proseCharsEach 或 prose 1.5 |
| 开局方向 prompt 编造新设定 | 中 | P2-1 强约束「只基于书内已填设定」，验收抽查 |
| 确认流复用改动影响现有章纲确认 | 低 | P2-3 只加分支，不动原逻辑；全量测试保底 |
| 工坊（workshop/orchestrator）已有新书逻辑（bookHasNoSubstantialBody 在用） | 低 | 分流只动 Agent 写作路径，工坊不动 |

---

## 6. 明确不做（边界）

- 不联网搜索市场/榜单（延续防编造规矩）
- 不做开局方向之外的新面板 UI（复用确认流）
- 不改工坊/批量路径（它已用自己的新书逻辑）
- 不做「新书自动出开局方向」的静默模式（必须用户参与选择，符合「给选项 → 用户选」）
