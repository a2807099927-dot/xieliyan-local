# 写梨眼：编辑器写作路径风格单入口 —— 任务清单

> 版本：v1（2026-08-03）
> 决策：拆掉编辑器路径的 `injectStyleToMessages` 二次注入，让编辑器「按细纲写作/按本章内容写作」与 Agent 写正文**完全一致**——只吃 bundle 单入口的风格。

---

## 目的（为什么拆）

「写作风格单入口收敛」（59a55b7）完成后，Agent 路径（write_chapter_body / runAgent）已经干净：风格只经 `buildWritingPromptBundle` 的 writer 单入口注入一次。

但编辑器路径（右键「按细纲写作」「按本章内容写作」）在 bundle 注入之后，**又调了一次 `injectStyleToMessages`**（`EditorContextMenu.tsx:579`），导致同一份风格在 prompt 里出现**两次**，且标题不同（「写手自定义提示词」vs「写作风格设定」）。

**问题不是「风格不生效」，而是「行为不一致 + 重复」**：
- 编辑器吃两遍风格，Agent 吃一遍——同一次写作，两条路径产出不同
- 重复注入浪费 token，两个不同标题可能让模型困惑

**目标**：全应用只有一条风格注入链——`buildWritingPromptBundle` 的 writer 单入口。编辑器路径去掉二次注入后，与 Agent 行为完全一致。

---

## 任务

### T1 去掉编辑器路径的二次风格注入

- **位置**：`src/components/editor/EditorContextMenu.tsx` 约 579 行
- **现状**：
  ```ts
  const finalMessages = config
    ? injectStyleToMessages(retryMessages, book.id, config, books, false)  // false = 不禁用，注入
    : retryMessages;
  ```
- **改法**：不再手动调 `injectStyleToMessages`，直接使用 `retryMessages`（bundle 已含风格单入口）：
  ```ts
  const finalMessages = retryMessages;
  ```
- **说明**：`buildOutlineWritingSystemPrompt` → `buildWriterSystemPrompt` → `buildWritingPromptBundle` 已通过 `resolveConfig`（`config || useConfigStore.getState().config`）从全局 store 读到风格并注入 writer rolePrompt，二次注入是冗余。
- **验收**：编辑器「按细纲写作」的 prompt 里风格只出现一次（【写手自定义提示词】段），无「【写作风格设定】」段。

### T2 排查并标记「不能拆」的路径（修正：3 处调用点）

- **排查结论（已核实）**：`injectStyleToMessages` 主动调用共 **3 处**：

  | 调用点 | 走 bundle？ | 注入性质 | 处理 |
  |---|---|---|---|
  | `EditorContextMenu.tsx:577`（按细纲写作） | ✅ 走 bundle | 二次注入 | **拆**（T1） |
  | `useAiChat.ts:242`（Agent） | ✅ 走 bundle | `disableStyle:true` 已禁用 | 不动 |
  | `useContinuationFlow.ts:114`（引导式续写） | ❌ **裸调 continuation_system，不走 bundle** | **唯一注入** | **不能拆** |

- **关键**：`useContinuationFlow` 的 `buildGuidedRetryMessages` 用 `getPromptSync('continuation_system')` 直接拼 system，user 只有「当前任务 + 光标前正文」，**不经过 bundle**——拆掉它的 `injectStyleToMessages` 会彻底丢失风格（回归）。标记为「已知例外」：裸调路径保留唯一注入。
- **验收**：EditorContextMenu 是唯一「走 bundle 又二次注入」的地方且已拆；useContinuationFlow 保留注入；useAiChat 不动。

### T3 顺带清理：EditorContextMenu 手动拼设定卡（评估，不改就说明理由）

- **现状**：`EditorContextMenu.tsx:568` 手动把 `buildStoryCanonBlock` 拼进 userContent——上一轮 writer 减负（`withStoryCanon:false`）后，这是**绕过减负**的补丁
- **评估**：编辑器「按细纲写作」是否需要设定卡全文？
  - 需要（设定一致性靠它）→ 建议在 bundle 对编辑器路径开 `withStoryCanon:true`，去掉手动拼，让路径统一
  - 不需要（参考章节 + 细纲已够）→ 直接去掉手动拼
  - **二选一，不能维持「bundle 关 + 手动拼」的割裂**
- **验收**：编辑器路径的设定卡来源单一（bundle 或手动，二选一），注释说明理由

### T3 验证编辑器风格仍生效

- 实测（dev 运行）：设置里改写作风格 → 右键「按细纲写作」→ 产出体现新风格（单入口仍然生效，只是不再重复）。
- **验收**：拆掉二次注入后，编辑器写作风格正常生效，无回归。

## 边界（不做）

- 不改 `injectStyleToMessages` 函数本身（`useAiChat` 的 disableStyle 逻辑保留）
- 不动 Agent 路径（已正确）
- 不动 `buildWritingPromptBundle` 单入口逻辑

1. 编辑器「按细纲写作」「按本章内容写作」prompt 风格只出现一次

3. 改风格后编辑器写作正常生效
