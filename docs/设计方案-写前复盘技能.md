# 设计方案：写前复盘技能化（pre-write reflection）

> 版本：v1（2026-08-03）
> 性质：给 DP 的实现规格 + 给用户的验收清单
> 关联代码：`src/Agent/skills/`（技能系统）、`src/Agent/agentUnifiedLoop.ts`（统一循环）、`src/Agent/tools/creativeTools.ts`（write_chapter_body）、`src/Agent/useAgentSession.ts`（runAgent 路径）、`src/Agent/outlineWritingContext.ts`（写作上下文）、`src/Agent/writingReflection.ts`（写后复盘，本方案不改它）

---

## 1. 目标与边界

### 做什么
给 Agent 加一个「写前复盘」阶段：动笔前先形成**可解释的写作决策**（承接点 / 怎么写 / 为什么这么写 / 加什么少什么 / 爽点与节奏），把决策文本展示给用户，并把结构化结论喂给正文生成。

### 不做什么（边界）
- **不动 `runPlanning`**：它是结构化约束（requiredBeats/forbiddenMoves），被 writer 消费、短指令跳过、shuangwen 跳过。写前复盘是文本化决策，独立存在，两者不合并。
- **不动 `writingReflection.ts`**：它是写后 Review/Revision 闭环（Generate→Evaluate→Rewrite）。写前复盘是 Generate 之前的决策，写后 review 负责验收。职责分开：复盘是计划，review 是验收。
- **不动 `loadReviewSkill`**：它仍是写后审查清单。题材打法是新技能，不复用 review 清单。
- **不引入真实市场数据抓取**：题材打法内容在技能文件里写死，标注「基于模型训练知识，非实时榜单」，防编造。

### 核心原则
1. 写前复盘是**强制**环节（每次写正文都做），除非用户显式关闭或 shuangwen 走轻量版。
2. 一次工具调用内完成「复盘 + 正文」两次生成，控制成本。
3. 复盘结论以 tool result 形式进上下文，模型无法忽略。
4. 复盘是意图声明（计划），不重复写后 review 的检查项。

## 2. 技能拆分总览

写前复盘由 **4 个技能**组成：2 个新增 + 2 个复用现有。

| # | 技能 id | 类别 | 性质 | 职责 | 触发 |
|---|---|---|---|---|---|
| 1 | `story_canon` | reference | 复用现有 | 设定卡 + 近期剧情卡 + 角色卡（承接点的事实底座） | 每次写正文前 |
| 2 | `genre_play` | reference | **新增** | 按题材给「市场打法」：读者预期 / 爽点类型 / 节奏模板 / 雷区（写死内容防编造） | 每次写正文前，按书 genre 加载对应文件 |
| 3 | `pre_write` | writing | **新增** | 写前复盘总成：五问框架 + 决策输出 schema，产出「决策文本 + JSON」 | 每次写正文前，最后加载 |
| 4 | `writing` | writing | 复用现有 | 写作方法论 / 写手 prompt 基座 | 正文生成时（已有，不动） |

**读取顺序（写正文前，固定 1→2→3）：**

```
[触发写正文]
   │
   ▼
1. load_skill('story_canon')   ← 承接点：设定 + 近章剧情 + 角色现状（事实层）
   │
   ▼
2. load_skill('genre_play')    ← 题材打法：按 genre 加载对应文件（事实层，写死内容）
   │
   ▼
3. load_skill('pre_write')     ← 写前复盘五问（决策层）：产出决策文本 + JSON
   │
   ▼
4. buildWriterSystemPrompt     ← 复用现有 writing 技能（基座，正文生成时注入）
   │
   ▼
5. 生成正文
```

## 3. 触发时机矩阵

| 路径 | 位置 | 触发方式 | 是否强制 | 备注 |
|---|---|---|---|---|
| unified loop 主路径（对话/续写） | `write_chapter_body` 工具内部 | 工具 execute 内先跑复盘生成，再跑正文生成 | ✅ 强制 | 模型调 write_chapter_body 即触发，绕不过 |
| runAgent 路径（useAgentSession 的 runAgent / 改写） | `buildAgentRewriteMessages` 之前 | 先跑一次复盘 chat，把决策文本追加进 messages | ✅ 强制 | 与主路径同一实现入口 |
| 编辑器右键一键写作（skipPlanning 路径） | `write_chapter_body` 工具内部 | 同上 | ✅ 强制 | skipPlanning 只跳 runPlanning，不跳复盘 |
| shuangwen | 同上 | 轻量版：只输出爽点节奏（不输出其他四项） | ⚠️ 轻量 | 无脑爽文要快，省成本 |
| 自动工坊 / 批量生成 | 二期接入 | 同主路径实现 | 默认开，设置可关 | 本期不做 |
| 用户显式跳过 | Agent 设置 | 开关 | 可关 | 写作新手要快节奏的退路 |

### 4.2 `pre_write`（写前复盘总成）

**存放**：`src/Agent/preWriteReflection.ts`（新文件，仿 `writingReflection.ts` 的纯函数结构）

**职责**（纯函数，不发请求、不碰 UI）：
1. `buildPreWritePrompt(...)` → 构建复盘 prompt（输入：book / chapter / taskSheet / storyCanon 块 / genrePlay 块）
2. `parsePreWriteResult(text)` → 解析决策 JSON（容错：纯 JSON / 代码块 / 截断，仿 `extractJsonObject`）
3. 导出 schema 类型 `PreWriteDecision`

**决策 JSON schema**：

```ts
export interface PreWriteDecision {
  /** 承接点：上一章结尾停在哪，本章从哪接（一句话） */
  continuation: string;
  /** 本章主线怎么推进：主要做什么、冲突是什么（2-3 句） */
  approach: string;
  /** 为什么这么写：与承接点的因果、与伏笔/长线的关系（2-3 句） */
  rationale: string;
  /** 主动加的东西：这章要埋的线头、要登场的关系、要推进的状态 */
  add: Array<{ what: string; why: string }>;
  /** 主动少写/不写的东西：避免拖节奏、避免重复 */
  remove: Array<{ what: string; why: string }>;
  /** 爽点与节奏（意图声明，不是验收） */
  pacing: {
    /** 开篇钩子：第一屏抓住读者（一句话） */
    hook: string;
    /** 本章爽点：1-3 个，每个一句话 */
    satisfaction: string[];
    /** 章末状态：结尾停在哪个点，留什么钩子 */
    endState: string;
  };
  /** 可读性注意：信息密度是否过高、是否头重脚轻（一句话） */
  readability: string;
}
```

**复盘 prompt 结构**（system + user）：
- system：以 `withBaseProse` 开头，声明「你是写前规划者，不是写手。先想清楚再让写手动笔。」强制「只返回 JSON，不要 Markdown 代码块」。
- user：拼接顺序 = 章节/指令 → storyCanon 块 → genrePlay 块 → 五问 → 输出要求。

**五问（决策层，全部基于上面已加载的事实层回答）**：
1. 承接点：上文停在哪？本章从哪接？（基于 story_canon）
2. 怎么写：主线怎么推进、冲突是什么？（基于 approach）
3. 为什么这么写：和承接的因果、和伏笔长线的关系？（rationale）
4. 加什么/少什么：主动加 vs 主动少写（add/remove）
5. 爽点+可读性：开篇钩子、本章爽点（≤3）、章末钩子、信息密度（pacing + readability）

## 5. 注入与生成流程（核心改动）

### 5.1 `write_chapter_body` 工具内部（主路径）

`src/Agent/tools/creativeTools.ts` 的 `write_chapter_body` execute 内，在现有 `callChat` 之前插入：

```
1. packed = buildOutlineWritingContext(...)          // 现有，不动
2. canonBlock = buildStoryCanonBlock(book, chapter)  // 或通过 load_skill('story_canon') 拿
3. genreBlock = loadGenrePlaySkill(inferGenreFromBook(book))  // 新
4. preWriteMessages = buildPreWritePrompt({...})     // 新：复盘 prompt
5. decisionText = callChat(preWriteMessages)         // 新：第一轮生成（短）
6. decision = parsePreWriteResult(decisionText)      // 新：解析 JSON
7. 把 decision 文本（决策展示版）拼进正文 userContent / system prompt
   → messages.push({ role: 'system', content: formatPreWriteDecisionForWriter(decision) })
   → 同时保留原 packed.userContent
8. out = callChat(正文 messages)                      // 现有，改传入 messages
9. 返回时把 decisionText 也带回（供 onThought 展示 / 落库候选）
```

**要点**：
- 复盘与正文是**同一工具调用内的两次 callChat**，不是两次工具调用，模型无法跳过。
- 复盘 JSON 作为 system 注入，写手必须遵守；同时以 tool result 形式进上下文。
- 若解析失败（`parsePreWriteResult` 返回 null）：不阻塞正文，降级为仅追加原始决策文本，不抛错。
- 若 `needsConfirm` 流程（现有）不变，正文草稿仍走确认。

### 5.2 runAgent / 改写路径

`src/Agent/useAgentSession.ts` 的 runAgent 与改写分支：
- 在 `buildAgentRewriteMessages` / `buildAgentRewriteMessages` 前，先跑一次复盘 chat（同一实现入口，抽成共享函数 `runPreWriteReflection(...)`）。
- 决策文本拼进最终 messages 的 system 或 user 前段。
- `skipPlanning`（编辑器续写）只跳过 runPlanning，**不**跳过复盘。

### 5.3 共享实现入口

新建 `src/Agent/preWriteReflection.ts` 额外导出：
```ts
export async function runPreWriteReflection(input: {
  book: Book;
  chapter: Chapter;
  taskSheet: AgentTaskSheet;
  callChat: (messages: ChatMessagePayload[]) => Promise<{ text: string }>;
}): Promise<{ decisionText: string; decision: PreWriteDecision | null }>
```
- 两条路径（write_chapter_body 工具 / runAgent）都调它，避免逻辑分叉。
- 内部负责：加载 canon 块 + genrePlay 块 → 构建 prompt → callChat → 解析。

### 5.4 shuangwen 轻量版

`runPreWriteReflection` 内检测 `taskSheet.primaryGenre === 'shuangwen'`：
- 换用 `buildPreWriteLightPrompt`：只输出 pacing（hook/satisfaction/endState）+ readability，跳过 continuation/approach/rationale/add/remove。
- 解析同样的 schema，缺的字段填空字符串。

## 8. 验收标准（猫猫虫验收用）

1. **主路径强制**：对话里让 Agent 续写，观察工具调用序列——write_chapter_body 内部先出现复盘生成，再出现正文生成；正文里不含决策文本、不含分析腔。
2. **决策可见**：用户在界面上能看到「写前复盘」思考内容（onThought 或工具 summary），包含承接点/为什么这么写/爽点，不是只有 JSON。
3. **shuangwen 轻量**：无脑爽文书续写，复盘只出爽点节奏，其他四项不出；正文生成正常。
4. **短指令不跳过**：指令 <10 字时 runPlanning 照旧跳过，但复盘照常执行（与 runPlanning 行为解耦）。
5. **解析失败降级**：故意让模型返回非 JSON（如 markdown 表格），正文仍能生成，不抛错、不死循环。
6. **开关生效**：设置里关掉后，工具调用序列里无复盘生成，直接出正文。
7. **写后 review 不变**：review_draft / writingReflection 行为与改造前一致。
8. **题材打法防编造**：genre_play 内容全部来自 md 文件，prompt 里看不到「实时榜单」「本周热门」类表述。
