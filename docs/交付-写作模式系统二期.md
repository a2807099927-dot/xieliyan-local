### A 组：新书 wizard 编排（5 项，对应一期 T3.2/T3.5）

#### P2-A1 wizard 状态机（核心）
- **状态持有**：`useAgentSession` 内新增 `agentTaskState`：
  ```ts
  {
    mode: 'new_book_wizard';
    step: 1..6;                    // 1方向 2档案 3写法 4规划 5大纲 6审查
    direction?: OpeningOption;
    coreArchive?: StoryCoreArchive;
    writingApproach?: WritingApproach;
    plotPlan?: VolumePlan;
    outline?: ChapterOutlineItem[];
    outlineReview?: OutlineReviewResult;
    userRequest: string;
  }
  ```
- **推进规则**：step N 产出 → 推气泡卡 → 用户确认 → step N+1；任一步可回退/修改（改完重跑该步 prompt）
- **落盘**：关键选择（direction/coreArchive/writingApproach）随确认写入 `agentMemory`（已确认态，**随 Book 落盘，不新增独立持久化文件**），供后续 step 及正文生成引用
- **文件**：`useAgentSession.ts`、类型定义
- **验收**：6 步按序推进；第 3 步改写法决策后回退重跑，不丢已确认的方向/档案

#### P2-A2 方向卡选择 UI（对应 T3.2）
- `AgentChatPanel.tsx` 新增方向选择卡：渲染 2-3 个 `OpeningOption`（title/pitch/outline/risk），点选一个
- 复用现有确认流模式（参照 `AgentChatPanel.tsx:4936` 章纲确认），**不动原逻辑**
- 点选后：`agentTaskState.direction = 选中项` → 自动跑档案 prompt → 推档案卡
- **文件**：`AgentChatPanel.tsx`
- **验收**：点选方向后自动进入下一步，气泡内容可滚动查看完整 pitch/outline

#### P2-A3 档案/写法/规划三步确认卡
- 三步共用同一套确认卡组件（标题 + 内容 + 确认/修改按钮），数据源 = `formatStoryCoreArchive` / `formatWritingApproach` / `formatVolumePlan`
- 修改按钮：弹输入框让用户提意见 → 重跑对应 prompt（带原产出 + 意见）
- **文件**：`AgentChatPanel.tsx`（通用确认卡组件）
- **验收**：三步卡内容正确；修改意见生效后重跑产出更新

#### P2-A4 大纲 + 审查联动
- 大纲卡（`formatChapterOutlineItem` 逐章渲染）→ 用户确认 → 自动跑审查 prompt → 审查结果卡（`formatOutlineReviewForUser`）
- 有 `invalid`/`needs_rework` 项时：显示「建议修改」按钮 → 重跑大纲 prompt（带审查意见）→ 重新审查
- 用户可跳过修改直接确认（尊重用户判断）
- **文件**：`AgentChatPanel.tsx`、`plotPlanning.ts`（接线）
- **验收**：审查标记的无效章能触发重写流程；用户否决后不强制重写

#### P2-A5 新书 wizard 与 runAgent 串联
- runAgent 检测到新书 → 初始化 `agentTaskState` → 不直接写正文，先推方向卡
- 6 步完成后 → 最终 outline 落细纲（复用 `formalize_chapter_outline`）→ 进正文生成
- **数据通道（写死）**：wizard 结论写入 `agentMemory`（confirmed 态）+ `book` 上新增 wizard 状态字段（如 `book.agentWizardState`）；`write_chapter_body` 从 `agentMemory` / `book.agentWizardState` 读取已确认结论注入上下文（档案 + 写法 + 卷规划 + 审查后大纲）
- **文件**：`useAgentSession.ts`、`creativeTools.ts`、`src/types/index.ts`（Book 字段）
- **验收**：新书对话「写第一章」→ 完整 6 步 wizard → 落纲 → 正文，全链路自动衔接；正文生成能读到 wizard 结论

### B 组：老书对齐触发（2 项，对应 T8.2 触发点）

> 一期已有对齐卡 UI + `agentContextConfirmed` 落盘 + 确认/驳回处理器，**只缺触发点**——`shouldReconfirmUnderstanding` 定义了没人调。

#### P2-B1 续写入口检测
- runAgent / rewriteSelection 入口：调 `shouldReconfirmUnderstanding(book)`，返回 true 时推对齐卡气泡（`bubble.understandingConfirm`）
- 推卡后**暂停续写**，等用户确认/纠正后再继续
- **文件**：`useAgentSession.ts`、`AgentChatPanel.tsx`
- **验收**：老书首次续写先弹对齐卡；确认后正常续写；再次续写不弹

#### P2-B2 关键变更重置标志
- `plotOutline` / 角色卡 / memoryBank 章节新增等关键变更后，重置 `agentContextConfirmed = false`
- 落点：`useBookStore` 相关 mutation 里加检测，或集中式 hook
- **文件**：`src/store/useBookStore.ts`
- **验收**：改大纲后再次续写重新弹对齐卡

### C 组：Agent 看章节（4 项，对应 T5.1~5.4）

> **风险最高组**。一期已实测三站：笔趣阁系 `#chaptercontent` 可用；番茄字体加密、起点验证码，**明确不做**（设计文档 §6 已写死）。

#### P2-C1 novel_browser 窗口依赖改造（前置，高风险）
- 现状：`novel_browser_open` 要求 novel-lab-window 已打开（`PARENT_LABEL` 硬编码），Agent 场景不可用；**且 execute_js 结果回传通道也绑在 novel-lab-window 上**（`novel_browser_exec_response` 的 `parent.emit` → `PARENT_LABEL`，另有 nb-bridge:// 协议、CSP 授权）
- 方案：给 Agent 用独立隐藏 webview 实例（不依赖 NovelLab 窗口），或把窗口依赖参数化（`window_label` 可传，Agent 用独立 label）；**回传通道同步改造**（emit 目标、nb-bridge 协议注册、CSP 授权都要覆盖新 label）
- **文件**：`src-tauri/src/commands/embedded/novel_browser.rs`
- **验收**：① NovelLab 未打开时，Agent 也能创建独立 webview 打开页面；② **独立 webview 打开页面后，`extract_page_text` 能把正文取回主进程**（不止「能开窗口」，还要验证 execute_js → 回传 → 主进程收到）

#### P2-C2 open_webpage / extract_page_text 工具
- 新增 `src/Agent/tools/webpageTools.ts`：`open_webpage(url)` + `extract_page_text(selector?)`
- 默认提取策略：`#chaptercontent` / `#content` / `.content` / `article` 命中即取；章节文本截断 3000-5000 字
- 注册进 `agentToolRegistry`（readOnly 类），unified loop schema 文本同步
- **文件**：`webpageTools.ts`（新增）、`agentUnifiedLoop.ts`
- **验收**：Agent 能打开笔趣阁系章节页并提取干净正文

#### P2-C3 read_url fallback
- 静态站优先 `read_url`（reqwest，已有）；novel_browser 留给 JS 渲染站
- `extract_page_text` 失败 → 自动 fallback `read_url` 抓 HTML
- **文件**：`webpageTools.ts` 内策略
- **验收**：同一 URL 两条路径都能读，fallback 不报错

#### P2-C4 反爬边界处理
- 提取结果为空/乱码/验证码页 → 返回「该站反爬无法读取」，不硬闯、不重试 N 次
- 判断：正文长度阈值（<100 字视为失败）+ 乱码特征（私用区字符占比高）
- **文件**：`webpageTools.ts` 内判断
- **验收**：番茄/起点 URL 返回明确「无法读取」，不卡死、不编造

## 2. 猫猫虫要点（开工前必读）

### 2.1 执行顺序建议（C1 与 A1/B1 并行，不串行阻塞）
```
并行开工：
  1a. P2-C1（窗口+回传改造）——风险最高先探路，C 组其他任务依赖它
  1b. P2-A1（wizard 状态机）——纯前端，不依赖 C 组
  1c. P2-B1（对齐触发）——纯接线，不依赖 C 组
随后：
  2. C2/C3/C4（看章节工具，依赖 C1）
  3. A2/A3/A4/A5（wizard UI 与串联，依赖 A1）
  4. B2（变更重置，依赖 B1）
  5. D1（研究闭环，依赖 C 组 + A 组）
  6. D3（全量验收）
```
**说明**：A/B 组与 C 组无依赖关系，别让高风险项卡住整个二期；但 C1 完成后优先接 C2-C4，避免探路成果悬空。

### 2.2 三条铁律（延续一期，别破）
1. **防编造**：所有 prompt 只基于书内已填设定 + 题材打法；研究结论必须来源标注，禁止「市场上流行 X」式无来源断言
2. **反爬边界**：看章节只做笔趣阁系等公开低反爬站；番茄/起点遇到直接返回「无法读取」，不硬闯、不重试、不编造
3. **不重复造轮子**：档案/角色卡/风格分析器/写前复盘/确认流全是现成的，只组装不重写

### 2.3 重点注意
- **P2-C1 是整组看章节的闸门**：不解决窗口依赖，C2/C3/C4 全白做。先给独立 webview 方案探路，别急着写工具
- **wizard 状态机要支持回退**：用户在第 5 步改主意回到第 3 步改写法，不能丢已确认的方向/档案——这是验收硬项
- **对齐卡「有 UI 无触发」是二期必须补的洞**：一期 UI/落盘都好了，只差 runAgent 入口检测那几行
- **研究闭环插在第 4 步前**：web_search → 读章节 → 结论卡 → 注入规划，别让研究结论悬空不用

### 2.4 提交纪律
- 二期任务完成后**提交推送**，发 commit 号（一期这次就是没提交，被核验抓到了）
- DEV_LOG.md 每完成一组更新一次
