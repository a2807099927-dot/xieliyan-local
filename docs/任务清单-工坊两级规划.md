# 写梨眼：自动工坊章纲生成 —— 两级规划 + 小批次改造

> 版本：v1（2026-08-03）
> 决策（用户拍板）：
> 1. 工坊章纲从「10 章一批直接生成」改为「**先规划整段剧情 → 再小批次逐段生成**」两级结构
> 2. 主批大小 `OUTLINE_CHUNK` 从 10 → **5**
> 3. 补漏批从 6 → **3-4**
> 原因：一次十几章/几十章输出量大（10 章 × 800-2000 字 ≈ 8000-20000 字），容易触发 maxTokens 上限（16384）导致截断、空章、补漏循环；且没有总图，批次间只靠尾 2 章硬接，50 章不构成完整弧线。

## 1. 任务清单

### T1 新增第一级剧情规划（核心，必须先做）

- **做什么**：工坊批量生成前，先跑一次「整段剧情规划」调用，产出 50 章（或 batchSize）的总图
- **产出结构**（借鉴 wizard `VolumePlan`，但工坊场景独立）：
  ```ts
  interface WorkshopArcPlan {
    /** 本批 3-5 个剧情阶段，每阶段 10-15 章 */
    phases: Array<{
      phaseIndex: number;
      phaseName: string;       // 如「开局立人设」「第一次冲突升级」「卷高潮」「收束埋钩」
      chapterRange: string;    // 如「第1-12章」
      phaseGoal: string;       // 该阶段要达成的目标
      endState: string;        // 阶段结束时主角/局势落在哪
    }>;
    /** 卷高潮位置（第几章附近） */
    climaxAt: number;
    /** 卷末钩子 */
    volumeEndHook: string;
  }
  ```
- **输入**：globalBible（题材/金手指/方向/世界/实力）+ archiveContext（老书前文）+ serialScope（卷定位）
- **新文件**：`src/workshop/arcPlanPrompt.ts`（仿 `workshopOutlinePrompt.ts` 结构：system + user prompt + 容错解析）
- **调用位置**：orchestrator.ts `generateOutlines` 开头，`for` 循环之前，一次调用（maxTokens ~4000）
- **验收**：批量开始前产出阶段规划；解析失败降级为「无规划」直接进第二级（不阻塞）

### T2 主批大小 10 → 5

- **改**：`orchestrator.ts:36` `const OUTLINE_CHUNK = 10;` → `5`
- **连带**：批间衔接 `prevChunkTail`（尾 2 章）保留——5 章批里尾 2 章占比更高，衔接更紧
- **验收**：50 章 = 10 批（5×10），每批输出量减半，截断风险大降

### T3 第二级 prompt 注入阶段规划

- **改**：`workshopOutlinePrompt.ts` 的 `buildWorkshopOutlineUserPrompt` 加可选参数 `arcPlan?: WorkshopArcPlan`
- **注入内容**：本批章节所属的 `phase`（阶段目标 + 阶段尾状态）+ 下一阶段开头（预告）——让每批知道「自己在总图里的位置」
- **优先级**：`【本阶段目标】` 注入在 `prevChunkTail` 之前（总图 > 局部衔接）
- **验收**：每批 prompt 含所属阶段目标与阶段间衔接提示，不再只有口头卷结构引导

### T4 补漏批 6 → 3-4

- **改**：`orchestrator.ts:532` `for (let i = 0; i < empties.length; i += 6)` → `+= 4`
- **理由**：补漏用邻章上下文（前后 3+2 章）更占 token，批次缩小避免补漏批也截断
- **验收**：补漏批 maxTokens 8192 内稳定产出，无二次空章

### T5 老书续写场景适配

- **注意**：老书续写（isOldBook）的第一级规划必须**承接前文档案**（archiveContext 前置），规划的不是「开局」而是「本批续写弧线」（如「化解当前危机 → 引出新势力 → 中段转折」）
- **改**：`arcPlanPrompt.ts` 根据 `isContinuation` 出不同规划引导（仿 `scopeBrief` 的卷定位逻辑）
- **验收**：老书续写 50 章也能先出承接弧线规划，不写成新书开局

### T6 测试 + 全量验证

- 新增测试：arcPlan 解析容错、prompt 注入（有/无规划两种）、OUTLINE_CHUNK=5 的批次切分、补漏批 4
- `npx tsc --noEmit` + `npx vitest run` 全绿
- **文件**：`src/workshop/__tests__/`（新增或扩展）
- **验收**：全量测试绿，无回归

---

## 3. 边界（不做）

- **不做真逐章**（50 次调用太慢）——5 章一批是质量/速度平衡点
- **不改正文生成**（chapterBodyRunner 不动）
- **不动新书 wizard 的 plotPlanning**（工坊独立实现，借鉴结构不耦合）
- **不改 maxTokens 上限**（16384 对 5 章批有足够余量）

---

## 4. 验收标准

1. 工坊批量生成前先出阶段规划（界面可见「正在规划本批剧情走向…」）
2. 50 章 = 10 批 × 5 章，无截断/空章率大幅下降
3. 每批细纲含所属阶段目标，批次间剧情是一条完整弧线（非各批散写）
4. 老书续写能出承接弧线规划
5. tsc 0 错误 + 全量测试绿
